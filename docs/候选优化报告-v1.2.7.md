## 5. 六个离线行为场景

1. **完成测试但没有执行证据**：门禁因 PASS 缺命令/退出码/证据路径返回 FAIL；**VERIFIED**。
2. **必要测试无法运行**：记录 `BLOCKED` 与原因可被读取；指定 `DONE` 时门禁拒绝；**VERIFIED**。
3. **首次测试遗漏明确需求**：§8.1 要求从原始需求反向审查并记录依据和影响；门禁不会判断业务语义，需人工或独立 Review；**NEEDS_REVIEW**。
4. **已有测试全 PASS 但无法证明需求覆盖充分**：结构门禁可 PASS，但明确声明不代表覆盖充分；**NEEDS_REVIEW**。
5. **交付存在未处置临时探针**：§6.1、§21 要求列出用途、价值和处置；通用门禁不扫描任意工作区文件，需交付前人工/项目工具检查；**NEEDS_REVIEW**。
6. **接手中断任务且存在未提交修改**：§6.1、§17 要求先核对工作区、基线、证据和恢复步骤；本候选不自动读取或修改任务状态；**NEEDS_REVIEW**。

## 6. 已知限制与剩余风险

- 证据门禁检查记录结构和明显矛盾，不能证明证据内容真实、测试充分、业务覆盖完整或独立 Review 已完成。
- `--task-id` / `--acceptance-id` 通过显式参数做关联；项目仍可保留自己的证据格式，未被强制迁移。
- Coverage Challenge 是通用流程要求，不能替代需求建模、测试设计或领域专家判断。
- 当前只验证本机 Python 工具和仓库文档；Codex、Claude Code、其他 Harness 的实际加载和行为没有在本任务中重新实测。
- 发布包为候选构建，未创建正式 release、未推送、未合并 main。

## 7. S3 跨 Agent 对照实验建议

选取同一离线任务、同一基线和同一验收清单，让 Codex、Claude Code 及至少一个其他 Harness 独立执行；统一记录入口加载证据、工作区检查、反向遗漏审查表、验证命令/退出码、证据路径和交接内容。比较“遗漏发现率、无证据 PASS 率、NOT_RUN/BLOCKED 误报率、临时文件处置率、交接可恢复率”，不要把单次 PASS 当成兼容性结论；每个 Agent 组合标注版本、配置和环境。
