# 05 · 会话交接与恢复

## 为什么必须写进仓库

会话上下文会丢、会被压缩、会换 Agent。**只有仓库里的文件是共享的。** 所以交接必须落成 `.vibecoding/HANDOFF.md`，而不是聊天里的总结。

## 写交接

```bash
python scripts/vb_handoff.py --project <项目> --task T-001 \
  --done "改了 src/calc.py 的除零分支" \
  --verify "31 tests OK（证据 .vibecoding/evidence/T-001.md）" \
  --blocked "无" \
  --next "补一个 0/0 的边界用例"
```

脚本自动填充：时间（带时区）、工作区（分支 / worktree / HEAD）、基线、当前 `git status` 摘要、证据目录清单；人工传入：已完成、验证、阻塞、下一步。

## 恢复（新 Agent 的第一条命令）

```bash
python scripts/vb_handoff.py --project <项目> --show
```

输出五段，正好是恢复所需的全部信息：

1. **交接正文**（HANDOFF.md 原文）
2. **当前基线**：分支、HEAD、是否有未提交改动
3. **证据清单**：`.vibecoding/evidence/*.md` 及各自结论行（`结论：PASS/FAIL/BLOCKED/NOT_RUN`）
4. **配置**：`.vibecoding/config.json`（标准版本与校验和 → 判断环境是否漂移）
5. **建议下一步**：HANDOFF 里的"下一步"＋未闭环项（结论非 PASS 的证据）

## 恢复纪律

- **先读再动**：确认 `git status` 里哪些改动是自己的、哪些是上一个会话留下的。不要把别人的改动 `checkout --` 掉。
- **不重跑有副作用的步骤**：交接里"已发生的外部效果"一节写了做过什么；先看它，再决定是否需要重做。
- **证据优先于记忆**：结论以证据文件里的退出码为准，不以"上个会话说通过了"为准。
- **环境漂移要重验**：`config.json` 里的 vendor 校验和与当前不一致 → 标准换过版本，之前证据可能失效（见证据里的 `Recheck Conditions`）。

## HANDOFF.md 字段（源自标准模板）

| 字段 | 内容要求 |
| --- | --- |
| `Updated` | 时间 + 时区 |
| `Task source` | 唯一任务记录路径（不要复制第二份任务表） |
| `Workspace` | 分支 / worktree / 路径 |
| `Baseline` | commit；有未提交改动则附 diff 标识 |
| `已完成` | 事实、改了哪些文件、为什么 |
| `验证` | 验收 ID、结论、证据路径、验证版本 |
| `未完成与阻塞` | 事项、原因、解除条件 |
| `已发生的外部效果` | 创建/写入/提交/发布；没有就写"无" |
| `工作区卫生` | 临时文件与处置 |
| `恢复步骤` | 先查什么、再做什么，避免重复副作用 |
| `下一步` | 可执行步骤 + 需要读的最少文件 |

## 反模式

- 交接写"详见上文/聊天记录" → 新会话没有上文。
- 只写"已完成"不写"验证过什么" → 无法判断能不能继续。
- 把任务状态复制到交接里当第二真值源 → 状态只认项目自己的任务系统。
